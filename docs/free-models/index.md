# 免费模型

这里收录我对公开可用、低成本或限时免费的模型的结构化解读。

这类文章不只看“能不能白嫖”，更关注三个维度：

- **能力边界**：它到底擅长什么，不擅长什么
- **使用成本**：除了价格，还看上下文长度、输出上限、速率限制、数据策略
- **适用场景**：适合聊天、代码、长文档处理，还是轻量 Agent 工作流

## 我会怎么读一个“免费模型”

### 1. 先看它免费得是否可持续

有些模型是长期免费，有些只是冷启动期免费，有些虽然单价为 0，但会有明显的速率限制、稳定性波动，或者随时调整策略。

所以“免费”只是入口，不是最终结论。

### 2. 再看它在工程上是否顺手

真正影响体验的，往往不是榜单分数，而是这些现实细节：

- 上下文窗口够不够大
- 输出上限够不够长
- 是否支持 function calling / tools
- 是否支持 structured output
- 是否支持 prompt caching
- Provider 的数据保留策略是否可接受

### 3. 最后看它能否形成稳定工作流

一个模型只有在以下条件同时成立时，才值得进入常用清单：

- 质量足够稳定
- 成本足够低
- 延迟与吞吐可接受
- 能接入现有 Agent / API / 自动化流程
